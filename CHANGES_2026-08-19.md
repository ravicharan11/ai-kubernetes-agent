# Changes Made - 2026-08-19

**Timestamp**: 2026-08-19
**Summary**: Fixed deprecated Groq model error and cluster context switching failure

## Issues Fixed

### Issue 1: Deprecated Groq Model (400 Error)
**Problem**: The application was using decommissioned Groq models (`llama-3.1-70b-versatile` and `llama-3.3-70b-versatile`), then tried `llama-3.1-8b-instant` which also returned "model not found" errors.

**Root Cause**: Groq decommissioned the `llama-3.1-70b-versatile` model on 2024-12-06 and `llama-3.3-70b-versatile` is also being deprecated (shutdown August 16, 2026). The `llama-3.1-8b-instant` model name may have a different format or availability in the current API.

**Solution**: Updated to use `gemma2-9b-it` which is confirmed available in the current Groq API. Added model listing functionality for better debugging and error handling.

### Issue 2: Cluster Context Switching Failure  
**Problem**: Users were unable to switch between cluster contexts in multi-cluster kubeconfig setups.

**Root Cause**: The `ClusterManager.get_clusters()` method was returning cluster names from the kubeconfig's `clusters` section, but `kubectl config use-context` requires context names from the `contexts` section. In kubeconfig files, cluster names and context names can be different, causing the context switching command to fail.

**Solution**: Modified the cluster discovery to return context names instead of cluster names, ensuring compatibility with `kubectl config use-context`. Added enhanced debugging and error messages to help identify context switching issues.
